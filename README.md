# Tabletop Board

Локальная совместная доска для НРИ. Реализованы Этапы 1–3: подключение ведущего и игроков, общий холст с изображениями и слоями, интерактивные заметки и текстовые стикеры. Листы персонажей и кубики относятся к следующим этапам.

## Совместимость

- Node.js 24 LTS, macOS Intel x64 и Apple Silicon; версия проекта закреплена в `.nvmrc`.
- Проверенное окружение: macOS 15.7.9, Intel `x86_64`, Node.js 24.5.0, npm 11.5.1. Рекомендуется последний патч ветки Node 24.
- Официальные сведения: [таблица релизов Node.js](https://nodejs.org/en/about/previous-releases), [архив Node 24](https://nodejs.org/en/download/archive/v24).

## Архитектура

Один Fastify-сервер обслуживает Astro frontend, HTTP API, загрузку файлов и WebSocket-команды. Astro собирает статический интерфейс, Konva рисует двумерный холст. Комнату, сессии, слои, объекты и метаданные ресурсов хранит SQLite; оригинальные изображения лежат отдельными файлами в `data/assets/` под случайными ID.

```text
src/
  pages/                 HTML-страница и оболочка интерфейса Astro
  client/app.ts          Konva-холст, заметки, стикеры, слои и библиотека
  shared/board.ts        Общие типы состояния доски
  styles/                Стили
server/
  index.ts               Fastify, HTTP, WebSocket и выдача файлов
  auth.ts, config.ts     Сессии и конфигурация
  board.ts               Проверка команд и прав доступа
  store.ts               SQLite, заметки, стикеры, проекции состояния и миграции
  assets.ts, images.ts   Хэширование, хранение и проверка сигнатур
  backup.ts              Копия базы вместе с оригиналами изображений
  *.test.ts              Проверки домена, HTTP, WebSocket и файлов
data/
  room.sqlite
  assets/<internal-id>
  backups/<timestamp>/room.sqlite
  backups/<timestamp>/assets/
```

Pan/zoom холста хранится в версионированном localStorage конкретного браузера и не рассылается участникам. Старый или повреждённый формат камеры сбрасывается к началу координат в центре экрана. Изменения доски идут через WebSocket-команды; сервер проверяет роль, владельца стикера и свойства слоя, записывает изменение в SQLite и рассылает каждому участнику разрешённую проекцию. Содержимое заметок запрашивается отдельным защищённым HTTP-запросом только при локальном открытии; WebSocket передаёт только доступные пользователю метки без текста и вложений. Загрузка изображения выполняется HTTP multipart-запросом; оригинал не перезаписывается при обрезке, отражении или трансформации.

## Зависимости

- `astro` и `konva` — статическая сборка и холст без React/Vue/Svelte.
- `fastify` и плагины для статики, WebSocket, cookie, multipart-загрузки и ограничения попыток.
- `better-sqlite3` и `dotenv` — локальное состояние и конфигурация.
- Dev-зависимости: TypeScript, Astro checker, `tsx`, `ws` и типы для тестов.

Версии зафиксированы в `package-lock.json`. Последняя проверка production-зависимостей через `npm audit --omit=dev` сообщила `found 0 vulnerabilities`.

## Установка и запуск

```sh
nvm use
npm ci
cp .env.example .env
```

`ROOM_CODE` для новой конфигурации — 6–8 букв/цифр в верхнем регистре из алфавита без `O`, `0`, `I`, `1`. Ввод кода не зависит от регистра. `GM_PASSWORD` должен содержать минимум 10 символов; парольные фразы с дефисами подходят. Секреты не передаются клиенту из конфигурации. Не публикуйте `.env`.

Ранее использовавшиеся коды длиной от 12 символов остаются приняты для совместимости. Текущий `.env` сохранён без изменений; менять его для запуска не требуется.

Для создания короткого случайного кода:

```sh
node --input-type=commonjs -e "const { randomInt } = require('node:crypto'); const chars = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789'; console.log(Array.from({ length: 8 }, () => chars[randomInt(chars.length)]).join(''))"
```

Запуск для разработки:

```sh
npm run dev
```

Откройте `http://127.0.0.1:4321`. Команда сначала собирает Astro, затем запускает backend с перезапуском при изменениях в `server/`. Для production используйте `npm run build`, затем `NODE_ENV=production npm start`; Secure-cookie включается в production. ngrok относится к Этапу 6 и здесь не настраивался.

## Этап 2: поведение и доступ

- Холст не имеет фиксированных границ. При первом входе начало координат находится в центре видимой области; последнее корректное положение восстанавливается отдельно в каждом браузере. Колесо меняет масштаб относительно курсора; пустое место можно перетаскивать. «100%» меняет масштаб, сохраняя точку мира в центре экрана. «Показать всё» центрирует и масштабирует видимые текущему пользователю объекты; пустая доска возвращается к началу координат.
- Принимаются PNG, JPEG и WebP. Сервер сверяет MIME с сигнатурой и размерами из содержимого. Максимум по умолчанию — 25 MB; также ограничено число пикселей изображения.
- Ресурсы дедуплицируются по SHA-256 и MIME. Объекты хранят отдельные координаты, размеры, слой, порядок, отражение, режим свободного растяжения и нормализованную обрезку. В режиме пропорций доступны угловые маркеры; сервер сохраняет пропорцию по исходному размеру ресурса и корректирует вторую сторону при изменении одной. Свободное растяжение сохраняется отдельно для каждого объекта.
- Обрезка — неразрушающая маска: исходное изображение целиком остаётся в прежнем масштабе, а сохранённый прямоугольник только ограничивает видимую часть. В режиме редактирования скрываемые края затемняются; границу можно двигать и менять её размер, затем подтвердить или отменить. Отражение учитывается при переводе координат маски; остальные объекты того же ресурса не меняются.
- При первом запуске после обновления SQLite добавляет `free_stretch` к таблице объектов. Существующие записи сохраняются, для них включается режим сохранения исходных пропорций.
- Слои имеют независимые настройки `visible`, `locked` и `audience`. Скрытый слой не отображается; `gm-only` слой полностью исключается из ответа игроку. Блокировка запрещает все изменения объектов на слое, включая ведущего и удаление самого слоя до разблокировки. Библиотека ресурсов доступна только ведущему.
- Изображения выбираются нажатием, выделение отмечается рамкой; пустая область снимает его. Для заблокированного слоя рамка остаётся видимой, маркеры и инструменты редактирования отключены, отображается значок замка.
- Изображения можно загружать кнопкой выбора файла или перетаскиванием одного/нескольких файлов в выделенную область библиотеки. Статус показывается отдельно для каждого файла; ошибка одного файла не отменяет остальные загрузки.
- Игрок может двигать только объект с разрешением `allowPlayerMove`, если его слой открыт и не заблокирован. Изменение размера, отражение, обрезка, перенос и удаление остаются только у ведущего. Эти ограничения проверяются сервером и не зависят от видимости кнопок.
- Оригиналы не удаляются при удалении объекта, поэтому общий ресурс не теряется, пока на него ссылаются объекты. Отдельная функция удаления ресурсов пока не добавлена.

## Этап 3: заметки и стикеры

- Ведущий создаёт, редактирует и удаляет заметки, задавая доступ: только ведущему, всем игрокам или выбранным участникам. Игроки не могут менять заметки.
- Список ведущего содержит только метаданные. Текст и вложенные изображения запрашиваются при открытии заметки; сервер повторно проверяет права и при выдаче файлов. Игрок без доступа не получает метку, текст или изображение. Открытие и закрытие заметки — локальное действие браузера.
- К заметке можно прикрепить изображения из существующей библиотеки, без копирования файла. Метку можно поставить и перемещать на открытом слое.
- Стикеры синхронизируются между участниками. Игроки могут создавать их на общем видимом незаблокированном слое; если такого слоя нет, сервер создаёт открытый общий слой для стикеров. Игрок меняет и удаляет только созданные им стикеры, ведущий управляет всеми. Размер текста выбирается из 12, 14, 16, 18, 24, 32 и 40 px; цвет текста — чёрный или белый.
- Метка заметки может быть текстовой с заголовком/короткой подписью или изображением из общей библиотеки ресурсов. Обе метки перемещаются, открывают заметку и попадают в проекцию только для пользователей с доступом к заметке.
- Изображения добавляются через компактное окно выбора с режимами библиотеки и загрузки: файлы можно выбрать кнопкой или перетащить в drop-зону. Загрузка показывает прогресс и результат каждого файла; успешные файлы сразу прикрепляются к текущей заметке. Используется общий upload с проверками формата, размера и SHA-256 дедупликацией. Удаление вложения из заметки удаляет только ссылку, а не файл библиотеки.
- Список заметок использует две строки на запись. Настройки метки, доступ, текст и ссылки на изображения хранятся в SQLite.
- Для прежних баз сохраняется устаревшее поле настройки разрешения стикеров, но оно больше не используется. Миграция схемы стикеров переводит прежние цвета в чёрный/белый и сохраняет остальные данные; старые заметки получают текстовую метку с названием по умолчанию.

## Резервная копия

После сборки выполните:

```sh
npm run backup
```

Команда создаёт `data/backups/<timestamp>/` с копией `room.sqlite` и всеми оригиналами изображений. Для восстановления остановите сервер и восстановите **и базу, и каталог `assets/`** из одной и той же копии. Храните backup вне публичного Git и, желательно, на отдельном локальном носителе.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm audit --omit=dev
```

Тесты проверяют корректность кодов и паролей, преобразования и подгонку камеры, пропорции и свободное растяжение, отражённую маску обрезки, сохранение обрезки и размеров после повторного открытия SQLite, безопасные миграции, dedup по содержимому, сигнатуры/MIME, multipart upload, доступ к файлам по текущей проекции, заметки и ACL-выдачу их содержимого, отсутствие текста заметок в состоянии доски, настройки стикеров и права владельца, команды GM/Player и WebSocket-синхронизацию трёх клиентов с повторным подключением. Проверки выполняются на уровне HTTP/WebSocket и геометрии; визуальную работу Konva и синхронизацию в двух реальных браузерах нужно проверить вручную. Автоматизированного теста отрисовки в настоящем браузере пока нет.

## Известные ограничения

- Реализован один постоянный игровой зал на сервер.
- Нет листов персонажей, сетки или кубиков.
- Нет ручного удаления ресурса из библиотеки; неиспользуемый файл сохраняется.
- Перепроверка Origin и rate limit за ngrok, а также полный внешний запуск относятся к Этапу 6.

## План

1. **Этап 1 — подключение:** выполнен.
2. **Этап 2 — холст, изображения и слои:** выполнен.
3. **Этап 3 — заметки и стикеры:** выполнен.
4. **Этап 4 — листы персонажей.**
5. **Этап 5 — PbtA 2d6.**
6. **Этап 6 — стабилизация, ngrok и запуск.**
